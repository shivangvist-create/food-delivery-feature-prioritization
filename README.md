# Food Delivery Feature Prioritization & A/B Testing

## Product Management Case Study

This project looks at a common product management problem in a food delivery app: there are many possible features, but the team cannot work on everything at the same time.

The main aim of this case study is to compare different feature ideas and decide which ones should be considered first.

## Problem

A food delivery application can receive many feature requests from users and business teams. Some features may have a high impact but also require a lot of development effort.

So, instead of selecting features randomly, I used a simple prioritization framework to compare them.

## Feature Prioritization

I used the **RICE framework** to compare the features.

The formula used is:

**RICE Score = (Reach × Impact × Confidence) / Effort**

Here:

- **Reach** – How many users could be affected by the feature
- **Impact** – How much the feature could improve the product
- **Confidence** – How confident we are about the estimates
- **Effort** – Approximate effort required to build the feature

## Features Considered

Some of the features considered in this analysis are:

- Smart Reorder
- Instant Checkout
- Scheduled Orders
- Personalized Recommendations
- Loyalty Rewards
- Live Order Tracking
- Group Ordering
- Subscription Plan
- Restaurant Recommendations
- Offers and Coupons

The features were compared using the RICE framework to understand which ones could provide more value relative to the effort required.

## A/B Testing

After prioritizing a feature, an A/B test can be used before making it available to all users.

The users can be divided into two groups:

**Control Group:** Existing version of the product

**Treatment Group:** Version with the new feature

The results can then be compared using metrics such as:

- Conversion Rate
- Repeat Order Rate
- Average Order Value
- User Retention
- Engagement

## Example

For a checkout-related feature, the main metric could be **Checkout Conversion Rate**.

If the treatment group performs better than the control group, the result can be investigated further before deciding whether to launch the feature more widely.

## Key Metrics

Depending on the feature, some useful product metrics are:

- Conversion Rate
- Cart Abandonment Rate
- Average Order Value
- Repeat Purchase Rate
- Retention Rate

## What I Learned

Through this case study, I worked with:

- Feature prioritization
- RICE framework
- A/B testing
- Product metrics
- User and business impact
- Product decision making

The main takeaway is that a product team needs to balance **user value, business impact and development effort** when deciding what to build first.
